# rationale comments for each -- keep editing THAT file by hand when adding/
# bumping a direct dependency. This file is the machine-generated, full
# closure (direct + every transitive dependency) that Docker/CI actually
# install from, so a fresh build is byte-for-byte reproducible -- closing
# the gap that let starlette (a transitive dependency of streamlit, only

# version on a cold rebuild and take production down (2026-08-05 incident,
# see project memory / the requirements.txt comment on the starlette line).
#
# To regenerate after changing requirements.txt: install requirements.txt
# into a clean environment THAT MATCHES PRODUCTION (the droplet itself via
# `docker compose exec app pip freeze`, or a container built from this
# repo's own Dockerfile -- not a bare local venv, which may resolve
# different platform-specific wheels than the Linux container actually
# runs), then replace this file's contents with that freeze output. Never
# hand-edit an individual line here without also bumping requirements.txt
# and re-verifying.
#

# regeneration -- justified only because starlette ships a pure-Python
# universal wheel (no platform-specific build to diverge on) and its own
# declared deps (anyio, typing-extensions) were confirmed already
# satisfied by this file's existing pins, so no cascading version changes
# were needed. Any future bump that isn't this narrow should still go
